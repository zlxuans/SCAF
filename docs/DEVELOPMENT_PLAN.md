# SCAF 分阶段开发与实验计划清单

更新日期：2026-10-19。本文作为后续逐阶段执行、检查和记录进展的主清单。

## 一、目标与当前状态

目标：研究面向低照度 RGB-D 视觉里程计的几何与时序可靠性感知描述子增强方法。基础特征提取器采用 SuperPoint，主要验证深度几何可靠性和时序跟踪可靠性两项设计是否带来可重复的收益。

当前状态：阶段 0/1/2 已完成，服务器 `/developer06/SCAF` 已通过工程环境检查和数据管线验收，记录见 [阶段 1 验收报告](STAGE1_REPORT.md)与[阶段 2 验收报告](STAGE2_REPORT.md)。算法模型、训练流程和正式实验尚未完成。已有申请书是研究设想，不作为算法有效性的证据。

## 二、本地、GitHub 与服务器的分工

| 位置 | 主要职责 | 保留内容 |
| --- | --- | --- |
| 本地项目 | 编辑代码、静态审阅、同步、检查结果、撰写论文 | 源码、配置、文档、必要的小型结果副本 |
| GitHub | 共享和保存可复现版本 | 代码、环境说明、协议、公开文档及经检查的小型汇总表 |
| 服务器项目 | 所有代码运行、CPU/GPU 测试、数据处理、训练和正式评测 | 与本地一致的代码提交、数据集、权重、完整日志和结果 |

默认在本地修改代码并提交，经检查后同步到 GitHub 和服务器。服务器主要执行训练和评测；如果确实在服务器上改了代码，先检查差异并同步回本地，再形成统一提交，避免两端独立修改同一文件。

每次正式运行记录：代码提交哈希、配置、依赖版本、数据清单及划分版本、预训练权重来源和校验值、训练种子、退化种子、设备信息、启动命令及输出位置。训练种子与图像退化种子分别记录。

服务器运行期间不更新其正在使用的源码目录。需要同时开发下一阶段时，为训练建立固定提交的独立工作目录；该能力在阶段 1 建立。每次运行采用独立输出目录，失败结果也保留记录。

## 三、阶段任务与验收标准

### 阶段 1：工程骨架、运行环境与实验协议

**目的：** 确保本地能编辑与同步、服务器能稳定运行和测试，同时先确定如何公平比较方法。

**任务清单：**

- [x] 盘点服务器 GPU、显存、驱动、Python、磁盘空间和数据存放位置，记录实际环境。
- [x] 建立隔离环境和依赖清单；所有 CPU 检查与 GPU 运行均在服务器 `/developer06/SCAF` 执行，本地仅编辑和同步。
- [x] 建立源码、配置、脚本、测试和文档目录，统一配置读取、随机种子、日志和输出目录约定。
- [x] 编写实验协议：固定输入分辨率、关键点预算、匹配规则、后端参数及各指标口径。
- [x] 建立单命令检查入口，以及服务器任务启动、状态检查、日志保存和断点恢复约定。
- [x] 建立固定提交的运行方式，检查代码同步不会改变已经启动的实验。

**交付物：** 可安装的工程骨架、环境说明、实验协议、最小检查命令、服务器运行说明。

**验收标准：** 服务器 CPU 检查通过且能够执行 GPU 张量计算；一个最小任务能生成包含版本和配置的日志；本地、GitHub、服务器的目标代码版本一致。此阶段不要求训练模型。

### 阶段 2：数据准备、场景划分与监督生成

**目的：** 获得可追溯、无划分泄漏的数据，并明确几何监督是否可信。

**任务清单：**

- [x] 清点本地和服务器可用数据，核对来源、使用条件、完整性和校验信息。旧项目中的数据可作为候选，旧实验结论不直接迁入本项目。
- [x] 选择公共 RGB-D 数据用于训练和验证，选择真实低照度数据用于独立测试；已核查并部署三条 TUM 序列及 ETH3D 手电筒序列。
- [x] 核验 RGB/Depth 时间关联、图像与深度配准、相机内参、深度单位、位姿坐标约定和真值来源。
- [x] 按场景分组，再按完整序列划分训练、验证和测试。共享同一场景的相邻片段不能分别进入训练集和测试集。
- [x] 实现可重复的低照度、噪声、深度缺失和深度扰动设置；保存退化参数及种子，并区分合成退化与真实低照度。
- [x] 根据深度、标定和参考位姿生成对应监督，处理越界、遮挡、无效深度、目标深度不一致与重复对应。
- [x] 保存并可视化少量投影和对应样例，人工检查几何方向及单位。

**交付物：** 数据清单、冻结的划分清单、加载器、监督生成入口、可视化样例、数据检查报告。

**验收标准：** 训练/验证/测试的场景与序列身份检查通过；正常样例投影正确，缺失和异常输入有明确处理；相同输入与种子可复现。没有可靠标定或参考位姿的数据，只进入适用的前端评测，不能强行计算轨迹精度。

### 阶段 3：强基线与统一视觉里程计评测

**目的：** 在实现新算法前，知道已有方法的效果、失败方式和计算成本。

**任务清单：**

- [ ] 接入冻结的 SuperPoint 特征提取器，保存特征坐标、描述子、置信度及提取配置。
- [ ] 实现统一的最近邻匹配策略、匹配过滤和几何评测入口。
- [ ] 接入官方 FeatureBooster 实现及匹配的预训练权重，核对描述子维度、坐标归一化和输入约定。
- [ ] 接入 SuperPoint + LightGlue，单独作为完整匹配流程基线。
- [ ] 建立所有前端共用的 RGB-D PnP/RANSAC 里程计后端，保留完整 SE(3) 位姿、时间戳和每帧状态。
- [ ] 实现匹配、轨迹和计时记录。ATE 使用不含尺度缩放的刚体对齐；RPE 根据相对 SE(3) 变换计算，并声明时间/帧间隔。
- [ ] 明确跟踪失败时的状态、轨迹中断和重启规则；报告覆盖率、失败次数和有效轨迹段，不能只保留成功帧。
- [ ] 验证空特征、匹配不足、重复时间戳、无效深度和 PnP 失败等情况。

**交付物：** 三类主要基线的统一入口、固定后端、逐帧记录、轨迹文件、基线报告和错误场景测试。

**验收标准：** 在开发/验证数据上跑通完整流程；三类基线的输入预算和硬件一致；匹配准确性有独立几何依据，不能仅用方法自身的 RANSAC 内点率代替；轨迹指标通过已知变换样例检查。正式测试集此时仅做文件与标定完整性检查，不用于调参。

### 阶段 4：几何可靠性感知描述子增强

**目的：** 判断可靠的深度几何关系能否改善低照度下的描述子区分能力。

**任务清单：**

- [ ] 保持 SuperPoint 冻结，以其描述子作为增强模块输入；第一版不重新训练检测器。
- [ ] 通过相机内参反投影三维点，构造帧内局部邻域和相对三维关系。
- [ ] 根据深度有效性、局部连续性等信息建立可靠性权重，并定义深度缺失时的外观分支处理。
- [ ] 实现局部描述子增强与归一化输出，明确与 FeatureBooster 已有设计的差别。
- [ ] 记录邻域搜索、聚合及额外存储开销，避免只统计神经网络部分的耗时。
- [ ] 完成前向、反向、填充掩码、空输入及全无效深度测试，并进行小样本训练检查。

**交付物：** 几何增强模块、对应配置、方法公式说明、测试及验证集小实验。

**验收标准：** 输出有限且维度正确；填充点不影响有效点；无效几何信息不会产生 NaN 或支配输出；训练能正常更新参数。小样本训练用于排错，不能作为泛化证据。

### 阶段 5：时序可靠性约束与匹配筛选

**目的：** 减少不可靠时序对应对训练和推理的影响。

**任务清单：**

- [ ] 计算前后向光流误差，并处理跟踪失败、边界和遮挡。
- [ ] 同时检查光流预测位置与实际候选匹配位置是否一致，避免把可靠跟踪错误地等同于可靠匹配。
- [ ] 构造时序可靠性权重，用于训练监督加权和推理匹配评分/筛选。
- [ ] 设计包含正负样本区分的训练目标与加权一致性项，防止描述子塌缩。
- [ ] 处理无正样本、所有权重为零、重复对应和填充点；明确各项损失的归一化方式。
- [ ] 分别开关训练中的时序约束和推理中的筛选，验证其独立影响。

**交付物：** 时序可靠性模块、训练损失、推理过滤接口、边界测试、方法说明。

**验收标准：** 训练与推理均可运行，损失与梯度有限；低可靠性样本的影响确实下降；不将双向光流一致宣称为动态物体剔除。若筛选让匹配数过少，必须同时报告跟踪损失。

### 阶段 6：正式训练与验证集选型

**目的：** 形成有记录、可恢复的模型，并在接触正式测试结果前固定方案。

**任务清单：**

- [ ] 建立训练/验证入口、检查点保存、断点恢复和最佳模型选择机制；记录优化器、随机数及数据顺序状态。
- [ ] 先小规模检查训练稳定性，再扩大训练；所有模型选择只使用验证集。
- [ ] 分别训练几何、时序、完整模型及必要的可靠性消融，保持训练数据和预算可比。
- [ ] 固定训练种子 7、13、29，至少完成三次独立训练；预训练基线不伪装成三个独立训练结果。
- [ ] 依据验证集确定阈值、邻域大小、损失权重和最终检查点，记录选择依据。
- [ ] 检查耗时、显存、损失、匹配质量和失败案例；训练损失下降不作为选型的唯一依据。
- [ ] 冻结代码提交、配置、数据划分、评价口径和检查点清单。

**交付物：** 三个训练种子的模型、完整日志、验证比较表、最终运行清单及复现命令。

**验收标准：** 训练完成且可从检查点恢复；模型选择过程未使用测试集；明确最佳方案相对基线的验证收益和代价。如果没有稳定收益，先回到阶段 4/5 诊断，不提前包装为论文贡献。

### 阶段 7：冻结方案后的完整测试与统计分析

**目的：** 验证两个设计是否在独立场景、真实低照度及统一后端中仍然成立。

**任务清单：**

- [ ] 执行冻结清单中的全部测试序列和预先定义的完整片段，禁止只挑选成功窗口。
- [ ] 分别报告正常光照、合成低照度和真实低照度结果；至少两个独立真实低照度序列作为正式证据目标，只有单序列时明确证据不足。
- [ ] 完成基本消融：基础特征、仅几何、仅时序、完整方案，以及普通几何聚合与加入可靠性权重的对比。
- [ ] 将训练约束与推理过滤的收益拆开，核对各模型的参数量、训练预算和后端设置。
- [ ] 执行噪声、深度缺失、深度扰动实验；深度鲁棒性实验保留干净参考几何用于评判，同时注明扰动是否影响里程计后端输入。
- [ ] 在相同设备上测试 256/512/1024 个关键点的精度与延迟，记录预热、GPU 同步方式及 P50/P95 延迟。
- [ ] 区分计算耗时和含数据读取的端到端耗时；冷启动与预处理缓存条件单独说明。
- [ ] 汇总三个训练种子的均值、标准差和每序列结果，同时保留匹配量、轨迹覆盖率、失败次数及失败案例。
- [ ] 生成可追溯的汇总 CSV/JSON、轨迹和图表；每个图表能定位到原始运行记录。

**交付物：** 基线/消融/鲁棒性/效率结果、统计汇总、图表、失败分析及实验结论。

**验收标准：** 完整实验矩阵执行并解释缺失项；结论同时考虑精度、速度、覆盖率和波动。算法贡献需要独立低照度测试与定位结果共同支持。若查看测试结果后继续调参，该测试集降为开发集；新的最终结论需要另一个未用于调参的测试集。

### 阶段 8：论文、图表与投稿材料

**目的：** 把已验证的工作组织成可以审阅、复核的论文。

**任务清单：**

- [ ] 按引言、相关工作、方法、实验、结论组织稿件，明确 FeatureBooster 等直接相关工作的关系。
- [ ] 仅把实验支持的增量写成贡献，区分描述子增强、匹配流程和视觉里程计三个层面的效果。
- [ ] 绘制方法框架、局部匹配可视化、轨迹、消融和精度—延迟图，保留可编辑源文件。
- [ ] 将摘要、正文、表格中的数值与汇总记录逐项核对，检查单位、失败序列和统计口径。
- [ ] 整理复现说明、补充材料和投稿信；核对第三方代码/权重引用及可发布范围。
- [ ] 投稿前重新核实期刊范围、篇幅、分区认定和免 APC 的订阅路线。
- [ ] 实时性证据充分时优先评估 JRTIP；主要贡献是视觉匹配效果时评估 MVA；SIVP 作为备选。最终选刊依实际结果与投稿时政策决定。

**交付物：** 可审阅论文、图表、补充材料、复现说明、投稿信草稿和投稿检查记录。

**验收标准：** 每个结论有对应实验记录，所有结果与实际方法一致，没有用拟实现内容替代已完成工作。正式提交前再核对作者、署名、基金及学校要求。
