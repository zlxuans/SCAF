# 实验协议 v2（阶段 3）

此文和 `configs/protocol.yaml` 约定基线及固定 RGB-D 后端的实现口径。本协议不是实验结果。v2 在 2026-10-19 明确阶段 3 的检测、双向比值检验、PnP 求解器、失败重启与计时统计；数据与几何监督继续使用数据协议 v1，不修改旧运行所引用的 v1 文件内容。历史协议可从阶段 2 提交读取。

## 输入与公平对比

- 同一序列的所有方法使用完全相同的帧、RGB/Depth 关联与退化参数。图像按比例缩小至不超过 640×480，不放大；同步缩放关键点坐标、深度与相机内参。深度采用最近邻采样，保留无效掩码。
- 深度单位统一为米。每个数据集显式指定内参、深度比例、配准方式、参考位姿来源及时间关联容差；不猜测缺失参数。
- SuperPoint 冻结，默认最多 512 个点；效率实验另测 256/1024 点。官方源码提交、权重 SHA-256、检测阈值 0.0005、NMS 半径 4、边界 4 像素在 `configs/baselines-v1.yaml` 固定。RGB 使用 OpenCV RGB2GRAY 后除以 255，直接调用官方 forward，不触发自动缩放。所有方法共享单次提取的坐标、描述子和分数。
- 增强前后的描述子采用 L2 归一化，直接比较使用欧氏距离、双向最近邻，两个方向均要求最近/次近距离比严格小于 0.8；任一侧候选不足两个时不通过。不能把平方距离直接与 0.8 比较；重复距离无法通过严格比值检验。几何和时序模块分别设置开关。LightGlue 使用官方完整匹配流程及默认适应性阈值，配置进入运行记录，不追加最近邻或比值过滤。
- FeatureBooster 采用官方 SuperPoint+Boost-F 权重，输入为 N×256 描述子及 N×3 的 `(x,y,score)`。坐标减去图像中心后除以 `0.7*max(width,height)`，score 原样保留。该基线统一采用上述提取设置，区别于其演示脚本的 0.015 检测阈值，不能称为原文设置的完全复现。源码和权重在独立资产清单登记，推理离线使用且禁止随机权重回退。
- 数据按场景/完整序列分组，训练与验证选择阈值，测试结果不得用于选型。合成低照度与真实低照度单列，训练种子和退化种子独立记录，默认均为 7/13/29。

## 匹配和轨迹

- 匹配正确性使用干净参考深度和参考位姿；重投影阈值 3 像素，深度一致阈值 `0.05 m + 0.02*z`。先判断源点深度、投影正深度、目标投影位置及遮挡；这些不确定时记为无法评判。候选位置深度缺失同样无法评判；候选深度有效但与源点深度不一致，或重投影超过阈值，则是错误匹配，不能排除出精确率分母。报告预测数、可评判数、正确数、精确率及未能评判原因。此评分不使用监督函数的一对一正样本分配；自身 RANSAC 内点率只作辅助指标。
- 固定 RGB-D PnP 后端：源深度反投影到 3D、目标关键点为 2D，EPNP + RANSAC，最少 6 个有效对应和 6 个内点，阈值 3 像素、100 次迭代、置信度 0.999。使用 RANSAC 共识做 LM 优化后重新检查正深度与重投影内点，不招入新的共识点。每对的 OpenCV 随机种子固定且各方法相同。后端不读取参考位姿，退化实验默认把受扰深度传给后端，干净深度仅用于独立评判。
- 保存 SE(3) 位姿和时间戳，运动为 `T_camera1_camera0`，位姿累积为 `T_world_camera1=T_world_camera0@inverse(T_camera1_camera0)`。失败时中断当前段；下一次成功帧间估计以前一帧的单位位姿起新段，不读取参考位姿重置，不填充失败帧、不跨失败边计算 RPE。
- 跟踪成功率为成功相邻选中帧间估计数/尝试数；覆盖率为至少参与一次成功估计的不同帧数/全部选中帧数，两者不互补。单个单位位姿起点不构成成功。报告所有段的长度、时长、最长段、失败边数；覆盖率 100% 也可能有多个不连通段。分段轨迹分别导出 TUM 文件，NPZ 保存段 ID、完整 SE(3) 及时间戳，不拼接成一条连续轨迹。
- ATE 使用同一时间关联后的 SE(3) 刚体对齐，无尺度缩放。RPE 用相对变换计算，间隔为相邻选中帧，分别报告平移米与旋转度；声明选帧步长和实际时间间隔。按段对齐仅作段内指标，不能当作完整轨迹 ATE。
- 训练、评测版本、数据/划分清单、权重校验和、后端阈值进入每次记录。缺真值或标定时不报告无依据的 ATE/RPE。

## 计时和统计

- GPU 计时先同步再起表、结束同步，避免只统计异步提交。预热 10 对，正式计时至少 100 对；短序列不足时标记限制，不通过重复同一帧冒充独立样本。
- 分别记录提取、增强（含邻域构图）、光流、匹配、后端与完整前端计算耗时；阶段 3 尚未启用光流，其耗时为 0。流式缓存仅保留前后两帧，各方法均计入共享提取的耗时；除首次建图起点外，每个帧间结果计入一帧的提取和增强开销。
- `frontend_ms` 为提取+增强+匹配；`pipeline_compute_ms` 再加后端；`input_plus_compute_ms` 再加图像读取与退化，明确是组件耗时之和。数据完整性检查、独立真值评判、结果写盘及多方法调度不计入这些列。整个作业 wall time 单列，不能把组件之和当作实际完整程序吞吐率。
- 标注设备、精度、分辨率、关键点预算、线程、预处理/缓存策略和版本。冷启动单列；报告 P50/P95、参数量和峰值显存。
- GPU 与其他任务共享时只能进行功能验证，不能发布性能基准。正式速度测试等独占或稳定空闲条件；同一批对比记录 GPU 初始占用。
- 逐序列结果和失败项完整保留；学习模型报告三个独立训练种子的均值与标准差。预训练基线的重复计时不能称为独立训练。

## 阶段 3 开发验收范围

`configs/stage3.yaml` 默认三条 train/val 序列，每隔 3 个已关联帧选择一帧，取前 120 帧，分别运行 clean 与 medium，共 18 项方法结果。每项 119 次估计，计时排除前 10 对，保留 109 个不同帧对；序列前缀用于功能验收，不能当成全序列结果。传入 `--max-frames 0` 可覆盖全部按步长选中的帧。测试角色在特征提取前拒绝执行。

验收固定单线程 CPU，不初始化 CUDA；记录 CPU 型号、主机负载和 GPU 初始占用，参数量为实际加载模型的全部参数，全部可训练参数为零。CPU 耗时是共享主机开发记录，峰值 CUDA 分配记为不适用；GPU 的同步计时、峰值显存及独占条件下的正式效率实验在阶段 7 完成。

## 运行记录与恢复

阶段 1 的 `scaf smoke` 输出到唯一目录：`manifest.json`、解析后的 `config.json`、`dependencies.txt`、`events.jsonl`、`checkpoint.pt` 和成功后的 `result.json`。运行失败保留状态与错误；UTC 时间用于机器记录，用户进度日期按 Asia/Shanghai。

`manifest.json` 保存 Git 提交与脏工作区标记、实际源码路径、配置、两个种子、设备清单、命令及依赖版本。阶段 1 的数据、划分、预训练权重字段明确为 null，后续接入真实实验后必须填写对应来源与校验信息。

基础设施恢复仅恢复 CPU 随机状态、已完成步骤和检查结果，要求源代码提交一致且工作区干净、关键配置一致。此检查不包含模型或优化器；完整训练检查点在阶段 6 实现模型、优化器、调度器、随机数、采样器及数据进度恢复。

以后修改协议必须更新版本并说明变更。不得把不同协议的结果混成同一对比。
